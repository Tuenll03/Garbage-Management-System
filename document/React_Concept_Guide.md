# คู่มือทำความเข้าใจพื้นฐาน React หน้าบ้าน (Frontend Concept Guide)

คู่มือนี้สรุปหลักการสำคัญ 4 เรื่องที่เป็นหัวใจสำคัญของการทำงานในระบบหน้าบ้าน เพื่อให้สามารถกลับมาทบทวนและทำความเข้าใจได้ง่าย ๆ ครับ

---

## 1. `useState` (กระดานไวท์บอร์ดอัจฉริยะ)

ใน JavaScript ทั่วไป เวลาเราอัปเดตค่าของตัวแปร หน้าจอจะไม่เปลี่ยนตาม แต่ใน React เราใช้ `useState` เพื่อบอกเบราว์เซอร์ว่า **"เมื่อค่านี้เปลี่ยน ให้วาดหน้าจอใหม่ทันที!"**

### 💡 อุปมาอุปไมย:
เปรียบเสมือน **กระดานไวท์บอร์ดพิเศษ** ที่มีตัวอ่านค่าบนจอ และมีปากกาเคมีวิเศษสำหรับเขียนทับข้อมูลตัวเก่า

### โครงสร้างโค้ด:
```javascript
const [score, setScore] = useState(0);
// score    คือ ตัวอ่านค่า (เอาไว้เขียนแสดงผลบนหน้าจอ เช่น {score})
// setScore คือ ปากกาเคมี (เอาไว้สั่งเขียนข้อมูลตัวใหม่ทับตัวเก่า เช่น setScore(score + 10))
// 0        คือ ค่าเริ่มต้นตอนเพิ่งเปิดหน้าเว็บครั้งแรก
```

## 2. `useEffect` (ผู้เฝ้าสังเกตการณ์เบื้องหลังฉาก)

`useEffect` ไม่ได้มีหน้าที่ไปแสดงผลตรง ๆ บนหน้าจอ แต่เหมือน **"พนักงานสอดแนมที่คอยตรวจตรา"** ว่าเมื่อเกิดเหตุการณ์ที่เรากำหนดไว้ ให้สั่งรันโค้ดชุดนั้น ๆ ทันที

### 💡 รูปแบบหลักที่ใช้บ่อย:

### แบบที่ A: เฝ้ามองแบบว่างเปล่า `[]` (ทำครั้งแรกและครั้งเดียว)
ใช้สำหรับ: **โหลดข้อมูลจากฐานข้อมูลหลังบ้าน (API) ทันทีที่เปิดหน้าเว็บนั้น ๆ ขึ้นมา**
```javascript
useEffect(() => {
    // โค้ดตรงนี้จะทำแค่ 1 ครั้ง ตอนเปิดหน้านี้เสร็จ
    console.log("หน้าเว็บแสดงผลเสร็จแล้ว ดึงข้อมูลหลังบ้านได้เลย!");
}, []); // <--- วงเล็บเหลี่ยมว่างเปล่า = ทำแค่รอบแรกครั้งเดียวพอ
```

### แบบที่ B: เฝ้ามองตัวแปรเฉพาะ `[count]` (ทำใหม่ทุกครั้งที่ค่านั้นเปลี่ยน)
ใช้สำหรับ: **สั่งคำนวณหรือทำงานซ้ำ เมื่อข้อมูลบนกระดานไวท์บอร์ดเปลี่ยน**
```javascript
useEffect(() => {
    console.log("คะแนนเปลี่ยนไปแล้วนะ!");
}, [score]); // <--- จะทำงานใหม่ทันทีที่ตัวแปร score มีการเปลี่ยนแปลงค่า
```

## 3. `sessionStorage` & `localStorage` (สมุดโน้ตของเบราว์เซอร์)

เมื่อเรากดรีเฟรชหน้าเว็บ (F5) ตัวแปรที่เป็น `useState` จะหายไปทั้งหมดเพราะล้างหน่วยความจำ RAM เราจึงแก้ปัญหาด้วยการฝากเบราว์เซอร์จดข้อมูลไว้

### 💡 ความแตกต่างของสมุดโน้ต 2 แบบ:
1. **`sessionStorage` (ใช้งานอยู่ในระบบปัจจุบัน):** ข้อมูลจะคงอยู่ตลอดเวลาแม้เรากดรีเฟรชหน้าเว็บ (F5) หรือเปลี่ยนลิงก์ไปมา แต่**เมื่อกดยกเลิกหรือปิดแท็บเว็บเมื่อไหร่ ข้อมูลจะถูกทำลายทิ้งทันที** 🔒 *(ปลอดภัยกว่าสำหรับระบบล็อกอิน)*
2. **`localStorage`:** ข้อมูลจะอยู่ถาวรในคอมพิวเตอร์ผู้ใช้ แม้ปิดเครื่องคอมพิวเตอร์ไปแล้วเปิดใหม่พรุ่งนี้ ข้อมูลก็ยังอยู่เหมือนเดิม *(เหมาะกับตัวเลือก "จดจำฉัน / Remember Me" ของเลขบัตรประชาชน)*

### 3 คำสั่งหลัก (ใช้กับ sessionStorage):
1. **บันทึกข้อมูล (Write):**
   `sessionStorage.setItem('isLoggedIn', 'true');`
2. **ดึงข้อมูลมาใช้ (Read):**
   `const status = sessionStorage.getItem('isLoggedIn');`
3. **ลบข้อมูลทิ้ง (Delete):**
   `sessionStorage.removeItem('isLoggedIn');`

## 4. ระบบสลับหน้า & ควบคุมสิทธิ์ (Role-Based Access Control)

ใน `App.jsx` เราต้องการคัดกรองว่าให้แสดงหน้าอะไร บนเงื่อนไขอะไรบ้าง

### 💡 การทำงานของเครื่องหมาย `&&` (และ) ใน React
ใน React หากเราเขียน `{ A && B && <Component /> }` 
หมายความว่า **"เงื่อนไขทั้งหมดด้านหน้า (A และ B) ต้องผ่านเป็นจริงเท่านั้น จึงจะยอมวาดรูปหน้าจอ Component แสดงออกมา"**

### ตัวอย่างการสลับหน้าตามระดับสิทธิ์ (Role) ของผู้ใช้งาน:
```javascript
// ดึงระดับสิทธิ์จากสมุดโน้ตเบราว์เซอร์มาเช็ก
const userRole = sessionStorage.getItem('userRole'); // เช่น 'Member', 'Officer', 'Admin'

return (
  <>
    {/* แสดงหน้าชาวบ้าน: ต้องกดเปลี่ยนมาหน้า homemember และคน ๆ นั้นต้องมีสิทธิ์เป็น Member เท่านั้น */}
    {currentPage === 'homemember' && userRole === 'Member' && <HomeMember />}

    {/* แสดงหน้าเจ้าหน้าที่: ต้องกดเปลี่ยนมาหน้า homeofficer และคน ๆ นั้นต้องมีสิทธิ์เป็น Officer เท่านั้น */}
    {currentPage === 'homeofficer' && userRole === 'Officer' && <HomeOfficer />}
  </>
);
```
**ประโยชน์:** ต่อให้ผู้ใช้งานที่เป็น "ชาวบ้าน" แอบแก้ไขหน้าจอของตัวเองด้วยเครื่องมือเบราว์เซอร์ให้กลายเป็น `homeofficer` ระบบก็จะไม่ยอมแสดงหน้าของเจ้าหน้าที่ขึ้นมาให้ เนื่องจากด่านตรวจ `userRole === 'Officer'` เป็นเท็จ (False) เสมอ

## 5. อธิบายโค้ดทีละส่วนใน `HomeMember.jsx` แบบ 100%

เพื่อให้เข้าใจการทำงานของโค้ดในหน้าสมาชิกร่วมกันทั้งหมด:

```javascript
function HomeMember({ onNavigate }) {
    // 1) สร้าง State "member" เพื่อเก็บข้อมูลคนล็อกอิน และ "loading" เพื่อเช็กว่าโหลดเสร็จหรือยัง
    const [member, setMember] = useState(null);
    const [loading, setLoading] = useState(true);

    useEffect(() => {
        const fetchMember = async () => {
            // 2) ดึงเลขบัตรประชาชนที่จดในเบราว์เซอร์มาเก็บใน storedCitizenId
            const storedCitizenId = sessionStorage.getItem('citizenId');
            
            // 3) ดักจับความปลอดภัย: ถ้าไม่มีเลขบัตร (แปลว่าแอบเข้ามาโดยไม่ได้ Login)
            if (!storedCitizenId) {
                onNavigate('login'); // ขับไล่กลับไปหน้า Login ทันที
                return;
            }

            try {
                // 4) ยิง API ไปขอรายชื่อสมาชิกทุกคนที่หลังบ้าน (Spring Boot)
                const response = await axios.get('http://localhost:8081/api/members');
                const members = response.data; // ได้ Array ของสมาชิกทั้งหมดในฐานข้อมูล
                
                // 5) นำเลขบัตรที่ได้จาก storedCitizenId ไปค้นหาคนที่มีเลขบัตรตรงกันใน Array
                const foundMember = members.find(m => m.citizenId === storedCitizenId);
                
                if (foundMember) {
                    setMember(foundMember); // ถ้าเจอ: เขียนข้อมูลคนนี้ลงไวท์บอร์ด 'member'
                } else {
                    onNavigate('login'); // ถ้าไม่เจอในฐานข้อมูล: ให้กลับไป Login
                }
            } catch (error) {
                console.error("เกิดข้อผิดพลาดในการดึงข้อมูลสมาชิก:", error);
            } finally {
                setLoading(false); // 6) ดึงข้อมูลเสร็จแล้ว (ไม่ว่าจะสำเร็จหรือพัง) ให้เลิกแสดงหน้าจอรอโหลด
            }
        };

        fetchMember();
    }, [onNavigate]);

    // 7) โค้ดส่วนดักสกรีนตอนกำลังดาวน์โหลดข้อมูลจากหลังบ้าน
    if (loading) {
        return (
            <div className="homemember-loading">
                <div className="spinner"></div> {/* แสดงผลวงกลมสีเขียวหมุน ๆ */}
                <p>กำลังโหลดข้อมูลสมาชิก...</p>
            </div>
        );
    }

    // 8) ประกอบชื่อและนามสกุลจริงของสมาชิกที่หาเจอ (ถ้ายังไม่เจอก็ให้แสดงคำว่า "ไม่ระบุชื่อ")
    const memberName = member ? `${member.prefix || ''}${member.firstName} ${member.lastName}` : "ไม่ระบุชื่อ";
```

## 6. สรุปลำดับการทำงานของการจำหน้าปัจจุบัน (Page Memory Flow)

เพื่อทำความเข้าใจให้เห็นภาพ 100% ว่า หน้าจอสลับและจำสถานะหน้าเดิมตอนกดรีเฟรช (F5) ได้อย่างไร:

```
[จังหวะปกติ: ผู้ใช้คลิกเปลี่ยนหน้า]
ผู้ใช้คลิกปุ่ม ➡️ หน้าลูกเรียก onNavigate('services') ➡️ หน้าแม่เซฟค่าลงสมุด sessionStorage.setItem('currentPage', 'services')

[จังหวะฉุกเฉิน: ผู้ใช้กดรีเฟรชหน้าเว็บ (F5)]
หน้าเว็บโหลดใหม่ ➡️ useState ตัวบนสุดของ App.jsx ตื่นขึ้นมาอ่านสมุดโน้ต ➡️ ดึงคำว่า 'services' มาแสดงผลต่อทันที
```

### การทำหน้าที่ร่วมกันของโค้ดใน `App.jsx` :

### 1) ขาจดบันทึก (ตอนคลิกเปลี่ยนหน้าปกติ):
ฟังก์ชัน `navigateTo` จะรันเฉพาะตอนที่มีผู้ใช้คลิกสลับหน้าเว็บเท่านั้น โดยมันจะ **เขียนชื่อหน้าเก็บเข้าสมุดโน้ต** เอาไว้:
```javascript
const navigateTo = (page) => {
    setCurrentPage(page); // สั่งสลับหน้าบนจอผู้ใช้ทันที
    
    sessionStorage.setItem('currentPage', page); // จดบันทึกชื่อหน้าใหม่นี้ลงในเบราว์เซอร์
};
```

### 2) ขาเปิดอ่าน (ตอนผู้ใช้กดรีเฟรชเว็บ F5):
เมื่อกดรีเฟรชหน้าจอ ข้อมูลตัวแปรใน RAM จะหายหมด แต่ตัวแปรเริ่มต้นใน `useState` ของหน้า `App.jsx` จะวิ่งไป **เปิดกระดาษโน้ตที่จดไว้มาอ่านและวาดหน้าจอเดิม** ขึ้นมาทันที:
```javascript
const [currentPage, setCurrentPage] = useState(() => {
    const isLoggedIn = sessionStorage.getItem('isLoggedIn');
    if (isLoggedIn !== 'true') return 'login'; // ถ้าไม่ล็อกอินดีดกลับไปเริ่มใหม่
    
    // ถ้าเคยล็อกอิน ให้เอาชื่อหน้าล่าสุดที่จดไว้เปิดขึ้นมาเลย (หากไม่มีประวัติให้ไปหน้าแรก 'homemember')
    return sessionStorage.getItem('currentPage') || 'homemember';
});
```

### 3) ขาลบทำลาย (ตอนกดออกจากระบบ):
เมื่อผู้ใช้กดออกจากระบบและย้ายกลับไปหน้าแรกสุด สรรพสิ่งในสมุดโน้ตของเบราว์เซอร์จะถูกล้างทิ้งเพื่อความปลอดภัยของข้อมูล:
```javascript
if (page === 'login') {
    sessionStorage.removeItem('isLoggedIn');
    sessionStorage.removeItem('citizenId');
    sessionStorage.removeItem('currentPage'); // ล้างข้อมูลหน้าปัจจุบันออกไปทั้งหมด
}
```

## 7. ความสัมพันธ์และการส่งข้อมูลระหว่าง `onNavigate` และ `navigateTo`

ใน React การส่งผ่านข้อมูลและการติดต่อสื่อสารระหว่าง **Component แม่ (Parent)** และ **Component ลูก (Child)** จะอาศัยหลักการของ **Props** และ **Callback Functions**

### 1) การเชื่อมโยงสายโทรศัพท์ (Parent-Child Connection)
* **ฝั่งแม่ (`App.jsx`):** มีฟังก์ชันจริงชื่อ `navigateTo` ทำหน้าที่เปลี่ยน State ของระบบ
* **ตอนเรียกใช้ลูก:** แม่ยื่นโทรศัพท์ให้ลูกผ่าน Prop ชื่อ `onNavigate`
  ```jsx
  <HomeMember onNavigate={navigateTo} />
  ```
  *(เปรียบเหมือนแม่ยื่นท่อส่งข้อมูลชื่อ `onNavigate` ไปให้ `HomeMember` โดยผูกปลายสายเข้ากับ `navigateTo`)*

### 2) การเรียกใช้งานและส่งข้อมูล (Callback & Parameter Passing)
เมื่อฝั่งลูกต้องการสั่งเปลี่ยนหน้า จะทำการเรียกฟังก์ชันที่รับมาทาง Prop และแนบข้อมูลลงในวงเล็บ (Argument)
* **ฝั่งลูก (`HomeMember.jsx`):** 
  ```javascript
  onNavigate('requestService'); // ส่งข้อมูลข้อความ 'requestService'
  ```
* **ผลลัพธ์:** ข้อมูลจะวิ่งทะลุช่องทาง `onNavigate` ย้อนกลับขึ้นไปหาฟังก์ชัน `navigateTo` ของแม่ทันที
* **ฝั่งแม่ (`App.jsx`):** รับข้อมูลจากลูกเข้ามาทำงาน
  ```javascript
  const navigateTo = (page) => { // ตัวแปร page จะได้รับค่า 'requestService'
      setCurrentPage(page);
      sessionStorage.setItem('currentPage', page);
  };
  ```

### 3) กฎและแนวปฏิบัติการตั้งชื่อ (Naming Conventions)
การตั้งชื่อที่ต่างกันระหว่าง `onNavigate` (ลูก) และ `navigateTo` (แม่) เป็นแนวทางการเขียนที่ดีเพื่อความเป็นระเบียบ:
* **ตัวส่งฝั่งลูก:** มักขึ้นต้นด้วย `on...` เสมอ เพื่อบอกว่าเป็นเหตุการณ์ (Event) เช่น `onNavigate`, `onClick`, `onChange`
* **ตัวรับฝั่งแม่:** มักเป็นคำกริยาตรงตัว เพื่อบอกถึงคำสั่งจริง (Action) เช่น `navigateTo`, `handleNavigation`
